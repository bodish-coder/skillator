# Launch proposals and handback

Read fixes.md/feedback.md, brand.md/brand.json and actual product evidence. Write
`.skillator/clone/launch/landing.md`, `launch/pricing.md` and
`launch/launch-plan.md` using the templates below. Keep the existing root
`.skillator/clone/listing.json` as the only store-listing input. Missing research
or an unbuilt feature is recorded as pending, not converted into a marketing claim.

## Landing: proposal, then design-arwen builds

Use [landing.md](../templates/landing.md): hero/one CTA and a real product image;
the top evidenced problems paraphrased in original words; three core-flow steps;
features tied to actual improvements; approved pricing; real objections/FAQ; final
CTA. Match the chosen voice. Invent no testimonials, user counts, star ratings,
press logos or trusted-by rows. The original's reviews are research, not the
clone's testimonials. Return the built page, applicable viewport/a11y/contrast
checks and each claim's supporting product/research evidence.

## Pricing: research and a proposal, owner decides

Use [pricing.md](../templates/pricing.md). Compare the original and relevant
alternatives using public source URLs, date read, currency, billing period,
seat/usage basis, inclusions and taxes where stated. Prices change: verify them
when doing the work. If research is unavailable leave the table unresearched;
do not make up current prices or imply a proposal is owner-approved.

Use linked/count-backed billing complaints from feedback.md to propose trial/free,
flat/per-seat/usage, monthly/annual and at most three audience-based tiers with a
rationale. State missing cost assumptions and cancellation/renewal protections.
List products/prices the owner would create after approval; do not create them,
choose live billing settings, or invent a discount. Preparing alternatives does
not transfer the owner's pricing decision to an agent.

## Listing and launch plan

Use the existing listing template and brand.md lint procedure, passing the actual
brand avoid names. Before an upload, verify current official store requirements:
screenshots, privacy/data-safety labels, policy/support URLs, age rating and review
access. The offline linter's stored limits are not a guarantee of store acceptance.
Use the Windows Store's current requirements manually; do not claim it is linted.

[launch-plan.md](../templates/launch-plan.md) records beta audience/consent, channels
supported by research, owner-approved draft announcements, initial user interviews,
analytics/error tracking, responsibilities, dates and stop/rollback criteria.
Writing outreach is not authorization to send it. Keep the original's identity out
of app names, listings and ads. Return proposals with owner decisions pending,
verified versus blocked checks, built-page evidence and the next preflight/deploy
handoff; never label an unexecuted launch successful.

HOW THE PTY WAS DRIVEN
  No tmux, no `script` on this host; /usr/bin/winpty exists but needs a console.
  pywinpty 3.0.5 (already installed in C:\Python313) opens a real ConPTY - the
  same pseudo-console Windows Terminal hosts - at 80 cols x 30 rows. A Python
  driver (scratchpad only) spawned the launcher in it, wrote keystrokes as bytes
  (arrow down = ESC[B, Enter = CR, backspace = DEL, tab = HT), and fed every
  byte the app wrote into pyte 0.8.2 (pip --target into the scratchpad, not the
  repo), a VT emulator, whose 80x30 screen was dumped after each key.
  Target board: a fresh `git clone` of the RUN-0014 worktree into the
  scratchpad per launcher (f55clone for ps1, f55clone-sh for sh); the clone's
  own launcher ran against the clone. The main checkout's board was never
  touched.
    ps1: powershell.exe -NoProfile -ExecutionPolicy Bypass -File <clone>\mods\ops-board\ops\ops.ps1 -Repo <clone>
    sh:  "C:\Program Files\Git\bin\bash.exe" --noprofile --norc -c "sh '<clone>/mods/ops-board/ops/ops.sh' '<clone>'"
  Key script: start, 2, 3, 1, down, t, n, type @qa-bot/QA Bot/qa@example.com,
  Enter, n, type @temp-x/tmp@example.com, Enter, backspace, y, t, a, Enter,
  down, d, Enter, q.
  No .skillator/team.md existed in the clone, so the team was built from the
  app itself (team add x2, team remove x1) before the assign.
  Every process was gone after each run (q exited 0; no node/powershell left
  naming the clones).

FINDINGS (not fixed - reported only)
  1. The brief's key script cannot land an assign on a repo with no
     .skillator/team.md: `a` Enter opens Add person (by design - "+ add person
     creates it"), and the following keys become form text. Run 3 added one person
     through the form; the assign/decide then landed exactly as the dialogs said.
  2. q from the Team view closes the whole board; that view's footer lists only
     "n add · del remove · esc back". Works, but q is undocumented there.
  3. ctrl+c with the board open closes the board in one press, form included (a
     half-typed Add person is dropped without asking). pi never exits on one press.
  4. Health under pi on Windows reads "Disk /tmp" (and "/tmp 103 GB" in the status
     row): pi's ticket-meta/facts calls run through sh ("ran: sh ..."), and the clone
     sits under %TEMP%, which Git Bash mounts as /tmp. The standalone ps1 launcher
     says "Disk C:" for the same machine. Cosmetic.
  5. pi lists three "Skill conflicts ... description is required" at every start:
     the installer copies PLATFORMS.md, PRACTICE.md and WORKFLOW.md into
     ~/.pi/agent/skills, and pi 0.74 tries to load top-level .md there as skills.
     Not an ops bug - an install-layout warning shown to every pi user.
  6. pi's first start in a fresh agent dir downloads fd and ripgrep before the
     editor appears; any keys sent sooner stall behind it (run 1). Host behaviour.
  The Runs tab showed "reading runs…" at 1.5 s and was left before it filled; the
  standalone run showed the list. Not timed further.

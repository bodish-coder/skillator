## Arwen rules the upstream contradicts

1. **Required vs optional marking.** Upstream: "Mark required fields (e.g. asterisk)" (qr:167). Arwen: "Mark **optional** fields, not required ones, when most are required (and the reverse)" (product-ui.md:51-52). **Arwen is right.** Mark the minority. GOV.UK and NN/g guidance agree, and fifteen asterisks tell the user nothing. Keep it.
2. **Toast lifetime.** Upstream: "Auto-dismiss toasts in 3-5s" (qr:169, also `ux-guidelines.csv:83`). Arwen: "~4–6s ... pause on hover, dismissible, never ... the only report of an error" (product-ui.md:207-209). **Arwen is right.** WCAG 2.2.1 requires adjustable timing, and pause-on-hover plus dismiss provides it. A fixed 3s toast with an Undo action fails anyone slow to read it.
3. **Springs vs ease-out.** Upstream: "Prefer spring/physics-based curves over linear or cubic-bezier" (qr:145). Arwen: "Ease-out exponential (quart / quint / expo). No bounce, no elastic" (craft.md:64). **Each is half right.** Arwen's own delegate `apple-design` (SKILL.md:365) teaches springs for gesture-driven motion. Upstream's "prefer" is too broad for CSS state changes. Fix in F23b: craft.md:64 should say "ease-out, or a critically-damped spring (no overshoot) where the motion follows a gesture". That keeps arwen's no-bounce ban.
4. **Touch target unit on web.** Upstream: 24×24 CSS px on web, and "do not substitute native units" (qr:28). Arwen: 44pt/48dp everywhere (SKILL.md:304, gate #10). **Upstream is right about the floor.** 44 is WCAG 2.5.5 (AAA). The AA floor is 2.5.8 at 24px, and dense product tables would fail arwen's gate as written. Keep 44/48 for touch and add 24 CSS px for pointer.
5. **Blur scope.** Upstream: "Use blur to indicate background dismissal (modals, sheets), not as decoration" (qr:90). Arwen: "Blur/vibrancy is idiomatic here (and only here)" meaning iOS (craft.md:144). **Upstream is right**, and arwen contradicts itself. craft.md:65-66 lists `backdrop-filter` and blur as legitimate premium motion on web. Change craft.md:144's "only here" to "native here, and a purposeful dismissal cue elsewhere".
6. **Test widths.** Upstream: breakpoints "375 / 768 / 1024 / 1440" (qr:97), and tests "on 375px" (pr:71). Arwen: 320/768/1280/1920 (verify.md:49, gate #7). **Arwen is right.** WCAG 1.4.10 reflow is defined at 320 CSS px, and 375 misses exactly the overflow arwen's gate exists to catch. Adding landscape is the only change needed (row 16).
7. **Type scale.** Upstream example: "12 14 16 18 24 32" (qr:119). Arwen: modular ≥1.25 for brand, fixed rem at 1.125–1.2 for product (SKILL.md:107-108, 169). **Arwen is right.** Its rule is a ratio you can check. Upstream's list is an ad-hoc ramp, and its ratio jumps from 1.125 to 1.5.
8. **Virtualisation threshold.** Upstream: "Virtualize lists with 50+ items" (qr:68). Arwen: "Under ~100 rows: render them" (product-ui.md:132). **Neither is canonical.** The cost is per row, not per count. Keep arwen's number and its "say which one you chose and why".
9. **The datasets vs arwen's shared floor.** Arwen adopts `anti-slop.md` whole (SKILL.md:281). Upstream's `data/typography.csv` builds **37 of its 74 pairings** on faces the floor bans (Inter ×12, Space Grotesk ×7, Plus Jakarta ×6, Outfit, DM Sans, Playfair, IBM Plex, Space Mono, Roboto; counted, verified). `data/products.csv:2` recommends "Glassmorphism + Flat Design" as the default for general SaaS, which is anti-slop §2's "glassmorphism as a default†". **For new choices inside an arwen task, arwen is right.** Arwen rejects first-order category reflex (SKILL.md:191-192), and that is exactly what upstream's product→style→palette lookup produces. When the user or a committed `DESIGN.md`/`MASTER.md` names one of these faces, the floor's own exemption applies and there is no conflict.

## Datasets and scripts

The whole skill dir is **3.7 MB** (`data/` 3.1 MB, `scripts/` 507 KB with tests). Arwen's whole dir is 120 KB. Everything is MIT, so copying any file means carrying the Next Level Builder copyright notice. The font data is metadata only: `google-font-licenses.json` records a per-family OFL/Apache license and sets `unlicensedFamiliesExcluded: true`. No font binaries are in this skill. The OFL `.ttf`s live in the sibling `ui-styling` skill. The scripts use only the Python 3 standard library (`csv`, `difflib`, `re`, `json`). Arwen promises "No setup, no scripts" (SKILL.md:28), which rules out copying any of them.

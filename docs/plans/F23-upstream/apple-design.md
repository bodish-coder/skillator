## Arwen rules the upstream contradicts

1. **Bounce.** craft.md:64 says "Ease-out exponential … No bounce, no elastic." Upstream SKILL.md:85-86 says damping 1.0 by default and ~0.8 bounce "only when the gesture itself carried momentum". **Upstream is right, and it is the narrower rule.** Both agree that a menu or reveal never overshoots. Arwen's blanket ban also forbids overshoot on a flicked card or a thrown sheet, where a critically damped stop reads as dead, and arwen's own delegate teaches the opposite. Fix: keep "no bounce" as the default. Add "except a spring released from a momentum gesture (flick, throw, drag release), damping ≥0.8, and never under reduced motion" (upstream :211 drops overshoot there). (inferred: judgment, not tested)

2. **Motion band vs press feedback and springs.** SKILL.md:107 sets product motion at "150–250ms, state-only". Upstream :38-41 sets press feedback at 100ms, and :82 says a spring "has no fixed duration" with response 0.3–0.4s (Quick Reference :277). **Both are right in different scopes.** Arwen's band is for state transitions. Press feedback must be faster, and a gesture-driven spring cannot be measured against a duration band at all. Fix: exclude `:active` feedback (≤100ms) and gesture-driven springs (judged by response, not duration) from the band. Otherwise a reviewer applying arwen will flag correct code. (inferred)

3. **Blur only on iOS.** craft.md:143-144 says "Blur/vibrancy is idiomatic here (and only here)". Upstream §12 (:181-197) builds web chrome from `backdrop-filter`. The shared floor (`references/anti-slop.md:41`) bans "Glassmorphism as a default†", which means as a reflex, not as a choice. **Arwen is right about defaults and wrong about "only here".** craft.md:65-66 also lists `backdrop-filter` as a legitimate motion material, so arwen contradicts itself. Fix: drop "(and only here)". Translucent chrome on web is allowed when it is the committed direction. When it ships, three rules apply: the reduced-transparency fallback (row 2), no translucent-on-translucent (row 10), and worst-case contrast under it (row 12). (verified: the lines conflict. inferred: which rule should win)

4. **System font first.** Upstream :234 prefers the system font. Arwen requires distinctive fonts in the brand register (SKILL.md:100, font procedure :171-182). **Arwen is right in its scope.** Upstream is a single-house style (Apple's own). Arwen's brand register exists to avoid exactly the default look. In the product register the two already agree (SKILL.md:105-106, 178-182). No change. (inferred)

5. **Not a contradiction, though it looks like one.** Upstream :262 "validate inline (not on submit)" vs product-ui.md:63 "Validate on blur, never per-keystroke". On blur is a kind of inline validation, so the two agree. Upstream's "Undo … confirmation only for genuinely destructive" (:252) matches craft.md:49-51. (verified by reading)
